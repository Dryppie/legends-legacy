# Milestone 6 Essence Optimizer

Milestone 6 adds a deterministic, diversity-aware search for strong legal Essence combinations. It optimizes Essence selection only: character level and the Region 1 reference Gear Package remain fixed for each E4/E5/E6 profile.

## Search Loop

The initial implementation uses an elitist mutation search, equivalent to a bounded genetic/beam hybrid:

1. Start from the legal random population generated by Milestone 3.
2. Add fresh legal random candidates when the requested optimizer population is larger.
3. Evaluate every new candidate against all five Milestone 4 PvE benchmarks.
4. Select elites using benchmark fitness with a diversity penalty.
5. Preserve elites without reevaluating unchanged genomes.
6. Fill most remaining positions with legal mutations of selected elites.
7. Reserve part of every generation for fresh random injection.
8. Repeat for the configured generation count.

The optimizer never mutates gear, character level, benchmark definitions, CR, or production content.

## Candidate Legality

Every candidate reuses the canonical build materialization boundary introduced in Milestone 3:

- exact slot count for E4, E5, or E6;
- unique Essence definition IDs;
- at most one Essence variant from each source monster;
- production definition and ability resolution;
- sufficient character-level slot unlocks.

A mutation replaces one or more selected Essences according to the mutation rate. Replacement families cannot duplicate a source already present in the genome. Candidate Essence IDs are sorted before signatures are calculated, making duplicate rejection deterministic.

## Fitness and Diversity

Base fitness is the equal-weight aggregate PvE benchmark score from Milestone 4.

Essence-set similarity is:

```text
shared Essence count / slot count
```

During greedy elite and retained-candidate selection, adjusted fitness is:

```text
aggregate benchmark score
- maximum similarity to an already-selected candidate × diversity penalty
```

The strongest candidate is always selected first. Diversity pressure affects subsequent selection, allowing an exceptional similar build to survive while discouraging a library of trivial one-Essence variations.

## Default Configuration

Defaults are deliberately bounded so the one-command pipeline remains practical on a developer machine:

| Setting | Default | Accepted range |
| --- | ---: | ---: |
| Population per profile | 20 | 4–500 |
| Generations | 4 | 1–100 |
| Elite count | 5 | 1 to population minus 1 |
| Mutation rate per slot | 0.25 | 0.01–1.00 |
| Random injection rate | 0.10 | 0.00–0.50 |
| Diversity penalty | 8 score points | 0–100 |
| Retained candidates per profile | 10 | 1 to population |

All settings are command-line configurable. Larger searches are intentional opt-ins rather than hidden defaults.

## Determinism

The balance-run seed, profile slot count, generation number, and candidate sequence derive stable search seeds. Every candidate is benchmarked with the same balance-run seed; the benchmark runner then derives its deterministic combat seeds from the candidate and scenario IDs. Previously evaluated genomes cannot re-enter a later generation under a new ID. Identical production content and optimizer configuration therefore produce identical genomes, fitness results, and generation summaries.

## Report Contract

Every balance run includes optimizer results in `summary.json`, summarizes initial-to-final improvement and diversity in `summary.md`, and writes complete retained candidates and generation summaries to `optimizer.json` under both `latest` and immutable history.

For each profile the report retains:

- initial and final best aggregate scores;
- best-score improvement;
- generation best, median, and worst scores;
- mean pairwise Essence-set similarity;
- unique genome count;
- a small diversity-selected final candidate set with Essence IDs and component scores.

The full transient search population is not persisted. [Milestone 7](milestone-7-representative-essence-builds.md) converts all unique evaluated candidates into explicit P50/P75/P90 representative profiles before that transient population is discarded.

## Initial Measured Result

With seed `8471`, ten Milestone 3 builds per E4/E5/E6 profile, and the default optimizer configuration, the completed pipeline measured:

| Profile | Initial best | Final best | Improvement | Final mean similarity | Leading build |
| --- | ---: | ---: | ---: | ---: | --- |
| E4 | 69.74 | 72.19 | +2.45 | 0.14 | `E4_OPT_G004_010` |
| E5 | 73.02 | 78.44 | +5.42 | 0.14 | `E5_OPT_G001_004` |
| E6 | 75.68 | 81.02 | +5.34 | 0.17 | `E6_OPT_G004_013` |

Every generation contained the configured 20 candidates and 20 unique genomes. The non-decreasing best score confirms elitism, while final mean pairwise similarity between 0.14 and 0.17 shows that the retained search did not collapse to near-identical builds.

## Verification Boundary

Automated coverage verifies:

- deterministic results for identical seeds and settings;
- legality and uniqueness of mutated and injected builds;
- configured population and generation counts;
- elite preservation and non-decreasing best fitness;
- random injection and diversity-aware retained selection;
- JSON and Markdown immutable-history output.
