# Loadout placement: scoped read-only native leases

Current status: optional native binding v8 now enforces read-only lease handles, finite acquisition attempts and concurrency, and cleanup before successful worker completion. Enclosing Python lease lifetimes, runtime/cache and finite observer bounds remain unresolved. Both compressed guards and the 1,806/1,800-second gate stay closed.

The target is the offline Balance Harness. `StudyWorkSupervisor(..., native_lease_budgets=...)` requires declarations for exactly `native`, `nativeAudit` and `publication`, alongside bounded pending families, managed retention and capped persistent sidecars. `RetainedOwner.run_worker(..., native_lease_budget=...)` supports the same explicit boundary. The declarations are copied and sealed with the pending plan before dispatch. No scientific launcher default changes.

`tower-proposal-native-leases-v1` declares an integer `maxConcurrentLeases` in 0..26. Native execution has a fixed catalogue of 24 racing lease paths, one for each of twelve roots and two arms, plus two enclosing-owner probe paths: the registry allocation lease and output lease. Each path permits one attempt. Audit and publication require a zero cap and prohibit all native lease operations. Normal acquisitions cannot use a probe role, and probes cannot use a racing role. Releasing a lease never refunds its attempt allowance. Paths are checked before parent creation or opening and cannot overlap protected worker inputs or sidecars.

The selected native command only needs empty leases, so the new scope opens original handles with read access, exclusive sharing and DeleteOnClose. It preserves the FileStream return type without retaining write access. Managed writes and resizing fail before growth and poison the scope, including when the caller catches the exception. A Windows correctness test also attempts a write through the original SafeFileHandle and verifies rejection. Existing v1-v7 and unscoped callers retain their original read/write stream behavior.

Scope ownership extends through explicit release. A release verifies empty content, closes once, checks that the lease path disappeared, and updates the original accounting collector. An abandoned handle is closed at scope exit but causes a failed receipt. A failed release retains conservative unresolved-handle state; it cannot become a successful release through a retry. Cleanup preserves an original worker exception and records additional cleanup failure separately. These are worker-scope lifetime guarantees, not a hard wall-clock limit. A hung worker action still depends on its enclosing process owner; no timer silently drops a live exclusion lock.

The two native probes check ownership held by another process or outer scope. Only a sharing/locking conflict from the actual open can establish a held lease. Missing ownership may create a temporary empty read-only lease; that handle is closed and the probe fails. Existing nonempty or unexpected lease files are rejected without opening or deleting them. Successful probes do not establish the byte or lifetime bounds of the enclosing Python owner's handles. Metadata, external operations, handle aliases, finalization/process-death cleanup and remaining observer work are outside complete coverage.

V8 requires the existing pending-family declaration and a distinct `nativeLeaseBudget` field. It emits work receipt v5 containing pending-storage v2 and native-leases v1 observations. Older bindings reject the new field, including an explicit null. Python independently validates catalogue membership, roles, attempts, acquisitions, held conflicts, releases, cleanup failures, concurrency and zero-byte claims. The owner verifies the bound budget, root, phase and receipt identity before retention. The supervisor retains lease observations per phase alongside pending observations and continues to distinguish complete, failed, missing and not-invoked workers. No extra sidecar is introduced.
