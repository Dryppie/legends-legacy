## Frozen implementation choices

Every eighth fresh request is uniform; an empty catalogue is always uniform. Guided requests form consecutive bundles for the same group. For N owners, baseline counts are the distinct values `[1, 1 + floor((N-1)/2), N]`; add one second filler draw at the middle distinct count. Thus N=10 spends four guided requests at counts 1/5/10/5, with filler variants 0/0/0/1. N=2 uses 1/2/2 and N=1 uses 1/1. Each subsequent catalogue sweep rotates all counts forward modulo N. This spends existing fresh requests, reducing catalogue breadth per short run; it adds no budget.

Derive placement and filler streams from policy, existing generation label, group ID and group-visit index, adding filler index only to the filler stream. Keep placement identical/nested across a bundle and use one baseline filler stream across its count variants. Changing reserved count can still change how coverage/filler consumes that stream; this is not a pure causal count experiment. A new filler draw may still duplicate a recipe or be impossible with limited inventory; do not resample to force success. Traces record visit, variant/count/filler indexes and derived stream labels alongside requested/placed/final group counts. Omit null variation metadata for old policies.

Reuse atomic group reservation and existing coverage/filler, legality, drift rejection and proposal charging. Consume fresh ordinals on rejected/duplicate requests; reset per arm.
