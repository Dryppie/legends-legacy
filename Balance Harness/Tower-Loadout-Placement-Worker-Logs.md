# Loadout placement: bounded worker stdout/stderr

Current status: worker logs have an opt-in retained-byte cap enforced by the parent process. Verification passes 456 Python tests, including a real native v4 audit with capped output. The target is the offline Balance Harness process boundary. `bounded_windows_process.run(..., log_byte_limit=...)` accepts a nonnegative signed-64-bit integer. The worker and its descendants inherit one pipe for merged stdout/stderr. The retained log file stays in the parent. A single synchronous reader checks available pipe bytes, reads at most 65,536 bytes per poll and writes only the remaining allowance. There is no unbounded output queue or background reader thread. The work deadline and caller checks remain active during sustained output and after root exit while descendants finish.

Output exactly at the cap succeeds. The first byte beyond it fails the invocation: at most the declared prefix is retained, pipe handles close, and the existing owned-job cleanup terminates and drains the process tree. Zero permits an empty log. Short file writes are retried using their accepted lengths. A thrown write may leave an unknown prefix; it stops capture and cannot establish completion. Existing logs are preserved by exclusive creation. Timeouts retain captured bytes and mark incomplete capture; they do not silently claim a complete truncated log.

The optional `tower-owned-log-capture-v1` observation records the cap, accepted bytes, bytes read from the pipe, independently checked closed length, overflow, EOF, completeness and error. Successful capture requires EOF and matching ordinary-file identity/length after close. The owner validates this block and rejects successful process observations with incomplete capture. Legacy calls keep their existing direct-file behavior and observation schema.

`StudyWorkSupervisor(..., worker_log_limits=...)` requires all four worker phases, copies their declarations, forwards the appropriate cap and checks the returned declaration. Each phase and normalized log path can be attempted once, preventing retries from multiplying the declared lifetime bound. With supervisor storage enabled, the storage binding retains the phase caps and its terminal observation reports their sum separately from managed-directory and original-sidecar caps. Scientific launcher defaults are unchanged.

These are bounds on parent writes to the retained worker logs, not filesystem confinement. They do not bound external mutations, other file paths, worker output attempts, pipe/kernel allocations, serialization or total owner memory. The monitor adapter's own console remains on the legacy path. Kernel job I/O now includes pipe traffic for bounded workers; parent log writes, closed-length samples and job transfer totals overlap or describe different scopes and must not be added as independent work. Logical bytes are not allocated or durable disk bytes.

The pipe design follows Microsoft's [PeekNamedPipe contract](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-peeknamedpipe) and [anonymous pipe operations](https://learn.microsoft.com/en-us/windows/win32/ipc/anonymous-pipe-operations). One reader owns the pipe and reads only reported available bytes. A full pipe provides backpressure; it does not establish a numeric kernel-memory bound.
