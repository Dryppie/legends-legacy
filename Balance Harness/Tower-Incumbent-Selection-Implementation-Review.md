# Incumbent nomination implemented and verified

**The opt-in `retained-composition-incumbents-v1` policy now keeps both admitted anchors eligible for independent selection. All 40 scoped tests passed, including current-content admission and native archive reconstruction from fabricated outcomes. No real combat or new production seed allocation occurred.** The previous practical pilot remains an unsuccessful improvement result; this implementation establishes nomination behavior, not stronger teams.

The new shortlist contains the two exact supplied anchor compositions and the two highest-ranked distinct non-anchor challengers. All four retain their existing discovery-rank order for selection ties. Descendants that carry anchor ancestry remain challengers. Missing supplied measurements invalidate nomination, and insufficient challenger evidence cannot start an undersized selection stage. The existing selection rule can return either an anchor or a challenger; it gives no guarantee against noisy selection choosing a weaker team.

The narrow first version requires improve-supplied mode, two distinct admitted references/starts, one construction root, one context, four nominees, one finalist, the existing zero-win health selector and no diagnostics/replays. Candidate legality, parent retention, operators, proposal accounting, random namespaces and ordinal ability order are unchanged. Exact fixture comparison confirmed identical discovery arms between old and new standalone policies. Existing standalone and paired supplied policies retain their previous behavior and defaults.

Use the existing preparation command with the explicit option:

```text
tower-retained-composition-prepare --definition <fresh-schema-3-json> --references <anchor-a,anchor-b> --output <new-directory> --policy-version retained-composition-incumbents-v1
```

The source must already satisfy the declared shape and budget; preparation validates supplied references and allocates no values. Omitting `--policy-version` still selects `retained-composition-v1`. The retained command rejects block policies. The prepared files produced by this verification contain explicitly synthetic schedules and must never be launched as a production study.
