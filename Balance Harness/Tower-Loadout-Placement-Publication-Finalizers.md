# Loadout placement: publication and sidecar finalizers

Current status: receipt publication and sidecar cleanup preserve first errors, close independently of accounting, avoid exception hooks and keep incomplete observations failed. Other nested finalizers, hard external/transient storage, whole monitor/caller memory and complete observer/cleanup lifetime remain unfinished. Both compressed guards and the 1,806/1,800-second gate stay closed.

The target is the offline Balance Harness. Receipt publication previously assigned an acquired stream only after its open-completion counter succeeded. An accounting failure could therefore lose ownership of the open stream. Close-attempt accounting could prevent close entirely, and secondary errors from counters, exception formatting or enclosing publication scopes could replace the original error. Cooperative sidecar construction/registration could also lose an acquired stream, while a failed close could be attempted again during scope exit.

Publication writers now retain the stream inside acquisition, before completion accounting. They attempt close independently of close counters and retain explicit open, publication and close-attempt state. Reuse is rejected. Sidecar acquisition closes an acquired stream if wrapper construction or registration fails, all registered writers receive independent cleanup attempts, and close is not retried after an error. One explicit close attempt does not guarantee successful release or bound a blocking operating-system call.

An independent failed flag prevents a publication observation from becoming `Complete` when accounting or error recording fails. Failed counters and error records are attempted separately without replacing the first exception. Incomplete numeric snapshots remain incomplete: the existing strict validators still reject them. Successful canonical bytes, positive short-write retries, flush/fsync behavior, sidecar limits, receipt schemas and version numbers remain unchanged.

Publication error records now use the fixed type `ExceptionDetailsOmitted` and message `Publication operation failed; exception details omitted.` The eleven secondary diagnostic literals contain at most **70 code points** and reuse the existing eight-entry ceiling for exact note lists. These paths avoid custom exception formatting, truthiness, attribute, annotation and metaclass-name hooks. Existing full or nonstandard note collections are left untouched, and annotation failures cannot replace the first exception. Original exception objects still propagate; their arguments, existing notes and traceback memory are not bounded by this change.

Legacy unobserved v1 worker receipts and v2 publication observations use explicit cleanup that preserves write or serialization errors through close failure. Enclosing v1-v4 worker/publication/persistence scopes preserve their body error through later publication failures. Required constructors run before file reservation where possible. Worker success, receipt publication and observation persistence remain separate outcomes: a failed worker can have a completely written failure receipt, and a failed receipt publication can have a completely persisted failure observation.
