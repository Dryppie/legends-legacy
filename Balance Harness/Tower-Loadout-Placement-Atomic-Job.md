# Loadout placement: job ownership during process creation

Current status: children enter their owned job during process creation, closing the separate assignment crash window. Hard external/transient storage, whole monitor/caller memory and complete observer/cleanup lifetime remain unresolved. Both compressed guards and the 1,806/1,800-second gate stay closed.

The target is the offline Balance Harness. The shared process helper previously created a suspended child and then assigned it to its job. An abrupt launcher exit between those operations could leave a suspended child outside the owned job. Normal exception cleanup reduced this risk but could not run after an abrupt owner exit. Microsoft's [description of the orphan window](https://devblogs.microsoft.com/oldnewthing/20230209-00/?p=107812) identifies creation-time job assignment as the remedy.

The helper now installs both `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` and `PROC_THREAD_ATTRIBUTE_JOB_LIST` in the existing extended startup structure. The first still permits only NUL stdin and merged output. The second contains exactly one configured owned job. Its handle remains non-inheritable and is absent from the standard-handle list. Windows assigns the child to that job during `CreateProcessW`. The job array and standard-handle array remain alive through attribute-list deletion. The existing 65,536-byte allocation ceiling now covers a list sized for two attributes. The [Windows attribute API](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) documents this mechanism and its Windows 10 / Windows Server 2016 minimum.

Kill-on-close and any optional commit/concurrency limits are installed before creation. The child stays suspended while the helper checks `IsProcessInJob`, records verified assignment and completes startup cleanup. Only then does it resume. The separate `AssignProcessToJobObject` call is removed. Unsupported or rejected job-list setup prevents creation without falling back. Failed creation never claims assignment. A false or failed membership query prevents resume, attempts direct root termination and retains unknown job coverage. When verified assignment precedes a startup-cleanup error, normal job termination/drain handles the suspended child.

This removes a specific ownership gap; it does not bound Windows termination latency or every cleanup call. A process handle held by the test parent does not prevent kill-on-close, but another retained job handle would affect that lifetime. The helper itself creates an unnamed non-inheritable job and never passes it as an inherited standard handle. Filesystem isolation, hard transient-storage quotas, monitor memory and complete observer/cleanup duration remain open. Whole-process coverage and scientific admission remain false.

Verification passes **610 Python tests in 27 groups**: **11 new atomic-job tests** and 599 current regressions. The new cases verify membership and an active job member before the creation wrapper returns in both log modes; exclusion of the job handle from inherited handles; failed or unsupported job attributes; false, failed or omitted membership; failed creation; and active-process-limit refusal during creation. Two retained abrupt-exit fixtures stop the owner inside the creation wrapper and during attribute-list cleanup. In both, the parent holds a synchronization handle to the suspended child before allowing the owner to exit with code 73. The child signals termination, and its execution marker remains absent. These are correctness checks, not timing samples or resource qualification.

Six existing Python test modules now inject failures at membership verification rather than the removed assignment call, or adapt their startup expectations to the job-list attribute. The broad-handle-inheritance negative control omits only the handle list, retaining atomic job ownership. Existing nested-job, job-limit, runtime environment, monitor I/O, cleanup, owner accounting and receipt tests all pass. Development smoke runs are excluded from the total.
