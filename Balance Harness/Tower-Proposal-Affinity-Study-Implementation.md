## Study and evidence

The controller binds the complete 3,948-value allocation before search. Each of twelve roots receives the two versioned 528-trial searches on common search panels. Both arms retain independent charges and native archives. A failed or cancelled root invalidates the study without replacement or resumption. Identical outputs remain in the twelve-root denominator.

Only after all 24 searches complete does the controller durably freeze their selected outputs, the fixed benchmark, every physical recipe, the held-out panel assignments, all search-report identities and the completed search-attempt prefix. No held-out measurement runs before that barrier. Within a root, matching physical recipes share one 256-trial measurement. Between roots, panels and measurements remain separate. The fixed search cost is 12,672; the held-out ceiling is 9,216; the total ceiling remains 21,888.

The result reports all twelve method and benchmark contrasts, absolute win counts out of 256, paired gains/losses, identical outputs, novelty relative to the three retained references, and changed proposal positions in each wave. It computes equal-root means, medians, worst roots, sample spreads and descriptive t intervals with eleven degrees of freedom. Paired seed standard errors and method/benchmark covariance are explicitly conditional on the frozen outputs. They are not estimates of future-root reliability.

The exact predeclared decision order and thresholds are enforced: incomplete studies cannot publish; then abandonment, no observed output differentiation, a larger fresh evaluation being warranted, or inconclusive. There is no adoption decision. The original [prospective JSON plan](Tower-Proposal-Affinity-Comparison-Plan.json) remains byte-for-byte unchanged, with file SHA-256 `f7840ded410c34a3283fd3424ec18af98cfc2057cee76181b02dfddf51666188` and canonical hash `3774a637af5e04d3d1683d244676d5723048c4eb97d69f0edee86a361fc690cd`.

## Ownership, reservation and publication

The launcher requires an externally pinned, complete admission package. Its request binds the plan, context, captured settings, full historical-value set, executable inventory and independent auditor. The package contains captured content and the retained runtime; substituting another DLL or inputs outside that package is rejected. A read-only input check does not itself admit the package.

The Windows launcher holds the registry-allocation and output leases until publication closes. It starts each worker suspended, assigns a Windows Job before resuming it, and verifies an empty process tree at completion. The native worker checks the enclosing owner, absolute deadline and both leases. Timeout, storage exhaustion, lost ownership and child failure prevent publication.

The scientific allowance remains 10,800 seconds and 6 GiB, including both audits and publication. Native work has 9,600 seconds and 5.5 GiB; auditing and publication share the remaining 1,200 seconds and 512 MiB. The second audit does not receive a fresh allowance. Completion and terminal receipts account for manifests and their own retained bytes. The launcher prints the external closeout SHA-256 required for later native verification. Admission preparation is separate work and must retain its own charge receipts; this launcher does not perform or silently absorb it.

Before exposing entropy, the worker authenticates the complete live history, copies the bound sources and content, retains the producing executable and all dependencies, and checks their inventories. Reservation writes a Pending sentinel first, then retains one fixed 16,384-word entropy batch without a cancellation point between exposure and durable storage. The first 3,948 acceptable distinct values are assigned in order. Every fresh exposed tail value is reserved. There is no refill. Interrupted reservation retains Pending and any exposed bytes; a new execution cannot reuse the output directory.

Every dispatched search and held-out attempt has a durable global Started entry before input preparation and a Completed entry only after report authentication. Local native freezes, charge journals and prepared-input identities remain retained. Windows readers share the existing writer's access while hashing the all-search prefix; the writer continues to exclude a second writer. A failed attempt remains charged and cannot be replaced.

Owned proposal adapters use the kernel's existing panel-freeze checkpoint mode. They append each local charge directly before dispatch instead of serializing the growing observation history after every attempt. The public proposal callback keeps its original full checkpoints. A parity test compares every archive file from the two paths byte-for-byte, including charges, input bindings, both generated batches, five panel freezes and the final search report. Separate interruption tests verify the unmatched charge on failed or cancelled preparation.

The worker produces `provisional-result.json` and a `MeasuredPendingAudits` receipt. The owner then runs native reconstruction, the independent Python audit and a native publication barrier as separate owned processes. It checks agreement and rehashes every pre-audit input before copying the final result. Failed runs retain technical evidence and reservations, with no completed result or closeout.

## Complementary audits

The native audit reclassifies the retained entropy; verifies source, content and executable bindings; reconstructs both proposal trajectories at every root; reproduces affinity-derived generation and prepared-input identities; authenticates literal battle reports; and rebuilds the global freeze, held-out measurements, attempt accounting and result. It executes zero fights. Auditing a real archive still prepares native inputs and therefore requires the qualified producing runtime.

The standard-library Python auditor separately reads literal gzip battle reports and trial ledgers, recounts all five racing panels, ranking, reference contrasts, diversity pruning, continuation scores, nominees and incumbent selection. It checks bounded single-edit lineage, legal essence/family placement, common search panels, the all-root barrier, physical held-out deduplication and exact panel membership. It independently recomputes reservation tails, fight costs, all endpoints, uncertainty summaries and the frozen decision. It neither imports the combat engine nor treats saved summary scores as observations. Native reconstruction additionally owns exact RNG trajectory, typed-affinity derivation and materialized-input hash verification.

Final native verification requires an external closeout pin, validates the full published inventory and resource/process receipts, repeats native reconstruction, and rechecks every file and the inventory before returning. The Python final mode also requires that closeout pin. Neither audit is an extra combat run.

Cross-language publication compares strictly deserialized result values, not exponent spelling: equivalent JSON such as `1E-07` and `1e-7` must agree, while an actual numeric change must fail. The numeric regression covers both cases and rejects unknown/missing result fields through the strict contract reader.
