## Implemented extraction and trust boundary

The [extractor](../TestResults/balance/tower-subgroup-protocol-20260916/extract.py) reads a bounded campaign snapshot and requires a caller-supplied campaign-manifest hash, frozen protocol, explicit panel binding and observed process exit. It checks manifest file membership/hashes and safe paths, complete campaign/batch counts, the four full scenarios, native source mappings, chunk receipts, ordered row identities, prepared bindings, evidence outcomes, balance counts and the separate durable `bulk-attempts.jsonl` journal. Every one of the 1,024 trial indices must have exactly one matching charged attempt. Duplicates, torn tails, retries and missing rows cannot be silently discarded.

The resulting export feeds the already audited comparison adapter. Native-shaped exports remain `UnattestedNativeOutcomeExport`; fixture exports remain `LiteralOutcomeFixture`. Neither the caller's manifest hash, supplied exit code nor an exported boolean can establish native execution authenticity. The extractor always reports nativeExecutionAuthenticated=false, promotionAuthorized=false and launchReady=false.

This Python layer does not reconstruct native report hashes, canonical native scenario/report serialization, or prepared-actor semantics. Those checks belong to the retained native verifier. After any authorized run, invoke `tower-balance-run-verify` under the pinned runtime and an owned process envelope, with the completed campaign-manifest hash unchanged before and after. Require a completed process receipt, zero owned processes remaining, the exact family/counts and an independent journal/chunk audit. A balance Fail/exit 1 is acceptable only as a completed scientific result after these integrity checks; exit 1 is never blanket success. Invalid/exit 2 and execution failures remain rejected. No completed native archive has been authenticated by this scope.
