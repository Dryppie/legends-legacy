# Loadout placement: scoped enclosing Python owner leases

Current status: optional enclosing owner leases now enforce two declared read-only paths, finite attempts and concurrency, and verified cleanup before successful supervisor completion. Hard elapsed-time, runtime/cache and finite observer bounds remain unresolved. Both compressed guards and the 1,806/1,800-second gate stay closed.

The target is the offline Balance Harness. `StudyWorkSupervisor(..., owner_lease_budget={"version":"tower-proposal-owner-leases-v1", "maxConcurrentLeases":2})` enables the new contract alongside declared supervisor storage. The authenticated admission package must capture the matching `proposal_owner_leases.py`, supervisor and launcher. This option composes with existing worker bindings, including native v8, without changing their schemas or enabling a scientific launch. Existing callers retain their lease behavior.

The fixed catalogue contains `<output.parent>/complete-family-allocation.writer.lock` and `<output>.writer.lock`. Each path has one acquisition attempt; release never refunds it. The declaration accepts a strict integer concurrency cap from zero through two. Successful ownership requires an overlapping pair, so a lower cap fails safely before worker dispatch. Unknown paths, Windows device/trailing-dot aliases, overlapping catalogues, linked paths and protected admission/accounting paths are rejected. Validation does not create parent directories.

The scope uses Windows `CREATE_NEW`, exclusive sharing, `GENERIC_READ | DELETE` and `DeleteOnClose`. The original handle cannot write or resize the file, and no handle is yielded to a worker. Existing empty and nonempty files are rejected without opening or deleting them. Size is checked through the original handle on acquisition and release. After closing, the path must be absent. This deliberately provides no stale-file recovery or retry.

The launcher's existing `ExitStack` owns ordinary release. The supervisor requires both handles to be held before each worker invocation and finishes the enclosing lease scope before owner closeout. An escaped handle is closed during scope cleanup but prevents success. A failed or ambiguous release is never retried or relabeled successful; its unresolved count remains. Cleanup retains the original failure, including `KeyboardInterrupt`, and adds cleanup errors as notes. Release accounting remains attached to the collector that acquired the handle.

The copied declaration, fixed catalogue and module hash are retained in the existing `storage-binding.json`. The supervisor checks the sealed plan before dispatch and retention. A versioned `ownerLeases` observation is persisted in the existing supervisor observation and included in the enclosing storage snapshot. Independent validation checks the exact catalogue, roles, attempt/acquisition/release counts, zero-byte claims, concurrent peak, unresolved state and scope completion. No new sidecar is required. Retained copies are overlapping snapshots, not additive work.

This is an explicit scope-cleanup boundary. It is not a hard bound on elapsed time: a hung owner action, blocking OS call, process death or remaining observer still needs an enclosing boundary. External mutations, raw aliases, directory metadata and finalization are not fully confined.
