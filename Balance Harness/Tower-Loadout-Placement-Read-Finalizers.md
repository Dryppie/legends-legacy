# Loadout placement: counted-read finalizers

Current status: counted reads preserve first errors through cleanup, attempt owned close once, retain borrowed-stream ownership and keep caught read failures from completing receipts. Receipt/nested finalizers, hard external/transient storage, complete monitor/caller memory and complete observer/cleanup lifetime remain unresolved. Both compressed guards and the 1,806/1,800-second gate stay closed.

The target is the offline Balance Harness. `CountedRead` previously used inherited context-manager cleanup, so a close error could replace a read, hash or parse error. Its close method also skipped base-wrapper finalization if the underlying stream close raised, leaving later explicit close or collection able to attempt cleanup again. Parser wrappers were not explicitly finalized. Owner text reads nested two context managers whose cleanup and failed-operation counters could replace the original exception. Caught read failures had no independent state preventing a caller from requesting a complete receipt.

Counted raw streams now retain explicit close-attempt state. An owned stream receives one explicit close attempt, and base-wrapper finalization is independently attempted even if the underlying close raises. Close does not allocate a failure-tracking context before mandatory cleanup. Repeated close and collection do not retry the owned close. Closed wrappers reject further reads, readinto, seek, tell and seekability queries. Context-manager exit preserves the body exception while attaching a fixed note for a secondary close failure. If wrapper construction fails after file acquisition, `open_read` closes the acquired file while preserving the construction error.

Ownership remains explicit: raw streams opened by the accounting module are owned; parser and decoding inputs are borrowed. `parse` now deterministically closes its wrapper while leaving the caller's input open. Decoding wrappers also leave their inputs open. A close attempt is not proof of successful release, and no hard deadline or guarantee about underlying implementation cleanup is introduced. Other nested codec and publication finalizers remain outside this change.

The collector retains an independent read-failed flag for acquisition, counted reads, seeks, parsing, decode setup/completion accounting and owner text reads. It is never cleared by later success. A caller may catch an error and return another result, but the counter receipt remains `Failed`; a completed API counter is not proof that the whole scope succeeded. Worker receipt scopes reject caught read failures before marking the worker successful. Receipt argument validation, schemas and versions are unchanged, and the existing owner/JSON failure states remain effective.

Owner text reads explicitly attempt text-wrapper close while retaining an earlier read or decode error. The raw wrapper still receives its own exit cleanup, without retrying an already attempted owned close. Failed-read and unknown-progress counters are attempted independently, and failed parse accounting cannot replace a parse exception. Successful encoding, BOM, newline, duplicate-key and nonfinite-value behavior remains unchanged. Raw file bytes, decoded bytes and parser-input bytes remain separate counters. Bytes consumed inside a thrown read are unknown to the counter and are not fabricated.

The three new secondary notes contain at most **53 code points** and reuse the existing eight-entry ceiling for exact note lists. Notes omit secondary exception details and avoid custom exception formatting, truthiness, attribute and annotation hooks. Existing full or nonstandard note collections remain untouched; annotation failure cannot replace the first error. Owner failed-counter notes retain their previously established 63-code-point bound. Existing exception arguments, notes, traceback memory and full read/parse memory remain unbounded by this mechanism.

Final verification passes **810 Python tests in 35 groups**: **37 new cases**, all 760 current regressions and 13 additional existing text-read/encoding/owner-routing cases. No group failed or required a failure retry. New tests cover simultaneous read/readinto/hash/parse and close errors, independent base close, no close retry during collection, borrowed ownership, use after close, constructor failure, failed byte counters, caught parser errors, decoder counters, text cleanup, cancellation, hostile hooks, bounded notes, annotation allocation failure and worker receipt rejection.
