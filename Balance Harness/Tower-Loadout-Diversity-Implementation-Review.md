## Implemented behavior

The pure [TowerLoadoutDiversity selector](../LL/tools/BalanceHarness/TowerLoadoutDiversity.cs) uses the existing combat rank, takes the first representative of each distinct per-character unordered loadout, then fills any remaining elite positions with unselected ordered recipes in rank order. Capacity remains four and the rank-one recipe stays first. Its signature serializes ascending numeric party slots and ordinal-sorted Essence IDs within each slot. Numeric slot identity, quantities, variants and exact case-sensitive IDs are preserved. The original build arrays are not reordered, and JSON encoding avoids delimiter ambiguity.

The [generation kernel](../LL/tools/BalanceHarness/TowerBossGeneration.cs) invokes this selector only for `loadout-diversity-joint`. Both v11 methods retain the v10 stagger-reservation constructor, compatible-defense metadata, providers, count draw, core/filler behavior and mutation portfolio. The new method has `fresh-loadout-diversity` provenance; its comparator keeps `fresh-stagger-reservation`. Existing methods keep their streams and serialized generation output. No new tuning parameter, reference field or score is introduced.

The resulting beam feeds the unchanged capability exploration, one-in-four exploration-parent branch, uniform parent draw and recombination union. Those pools can change as a consequence of the beam. `Rank`, fitness, shortlist and validation primary rules remain unchanged. Ordered recipe IDs/cache entries remain separate: grouping is a parent preference, not combat equivalence. All defaults, catalogs and gameplay remain unchanged.

Policy/provenance admission is updated in [TowerBossDiscoveryContract.cs](../LL/tools/BalanceHarness/TowerBossDiscoveryContract.cs). The existing v10 metadata path also admits v11 in [TowerBossPartyGenerator.cs](../LL/tools/BalanceHarness/TowerBossPartyGenerator.cs), [TowerPartyCoverage.cs](../LL/tools/BalanceHarness/TowerPartyCoverage.cs) and [TowerStaggerReservation.cs](../LL/tools/BalanceHarness/TowerStaggerReservation.cs). These are validation/dispatch changes; source-derived provider extraction and the control count rule are not changed.
