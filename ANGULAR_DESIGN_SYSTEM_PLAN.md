## Summary

The game already runs no React. React lives only in Grimoire's reference edition (`design-system/components/bundle.js`, 57 catalog previews and the parity harness). It is not in `package.json`, not in `package-lock.json` and not in the game bundle.

The real problem is the Angular edition the game uses: 44 `lg-*` components and 4 directives, 5,424 lines, held to React's DOM by the parity rule (D-093). It inherits React's shape: `display: contents` hosts, configuration arrays instead of composition, a string `lgSlot` standing in for ReactNode props, hand-rolled overlays and focus code, one shared 134 KB global stylesheet, and no unit tests of its own.

Recommendation:

- **One edition.** Angular becomes the only implementation. Keep `tokens.json`, `icons.json`, the fonts, the assets, the docs and the decision log. Retire `bundle.js`, the vendored React 18.3.1, the previews, the catalog and the parity harness.
- **Inside the app.** Move the code to `src/app/grimoire/` behind an `@grimoire` path alias. No library project, no second app.
- **Re-shape now.** Rework the 44 existing components into Angular idioms while only two consumers exist (Character Overview and the new shell, both behind New look). Then add the missing primitives (form controls, overlays, feedback, tables) on the Angular CDK.
- **Showcase in the app.** Replace the React catalog with a dev-only `/grimoire` route plus Playwright screenshot baselines. Storybook for Angular 20 builds with Webpack, outside the app's esbuild and PostCSS pipeline; revisit it after an Angular 21+ upgrade.
- **Validate on two screens.** Settings (forms, dialog) and Inventory (items, rarity, overlays, table) before migrating the rest.

React removal comes early (phase 2), not last. Nothing in the game depends on it, and while it stays every design-system change is made twice. This supersedes step 3 of the 2 October agreement ("keep both editions").

## 1. Current Design System architecture

Grimoire has two editions of every component, kept equal by a check, and the game uses only the Angular one. Paths are relative to `LL/src/Presentation/ll/`.

Every design-system change is six edits today (the "one change" rule in `design-system/AGENTS.md`): docs, tokens, README and preview, `bundle.js`/`.css`/`.d.ts` and the API card, the decision log, and the Angular port with its parity case.

### What is React-shaped in the Angular edition

- **Hosts that are not boxes.** Nearly every component sets `host: { style: 'display: contents' }` and renders React's root element inside it. The host can't be styled, positioned or given a role, and `Panel` and `Ledger` null out `title` to stop a native tooltip.
- **Configuration arrays instead of composition.** `lg-nav-rail [sections]`, `lg-ledger [rows]` and `lg-chronicle [channels]` build their rows inside the component. A feature can't add a `routerLinkActive`, a tooltip or an extra element to one row.
- **`lgSlot="aside"`.** One string-typed directive stands in for every ReactNode prop, checked at runtime through `contentChildren(LgSlotDirective)`.
- **`interactive` plus `(activate)`.** ItemSlot, LoadoutSlot, CurrencyPill, ItemLink and Activity render a button when React would have received `onClick`, instead of letting the author write `<button>` or `<a routerLink>`.
- **Hooks ported as globals.** A module-level layer stack with its own document `keydown` listener (`lgOpenLayer`, from `LL.layers.use`), an own announcer, `lgMoveKey` roving focus, a hand-built combobox in SearchField and `setTimeout` focus in GameShell's drawer. The CDK, already used in 25 files of the app, does all of this, and today the two stacking systems run side by side.
- **One global stylesheet.** All component CSS is a single unscoped 134 KB file shared with React and loaded for every player. The lazy `lgLoadStyles` link exists only to keep it out of the first load.
- **No tests of its own.** Correct means "same DOM as React". Delete React and the 5,424 lines have no safety net.

## 4. Angular target architecture

Grimoire becomes an ordinary part of the Angular app: a folder of standalone components, directives and pipes that features import, built on the Angular CDK, with its values generated from `design-system/`. It knows nothing about the game's data.

```text
design-system/ (tokens.json, icons.json, docs) --builds--> src/app/grimoire (@grimoire)
  tokens and styles -> core -> primitives -> components -> game -> shell
  (each layer uses only the layers above it; Grimoire uses the Angular CDK)
Feature screens (features/*-grimoire, adapters) --imports--> @grimoire
Feature screens --use--> game services, DTOs, SignalR
@grimoire --NEVER--> game services, DTOs
Showcase (/grimoire, dev only; snapshots and axe) --imports--> @grimoire
```

Tokens and icons are generated from `design-system/`; features fetch game data through their services and hand Grimoire display values only.

| Tier | Where | Owns | Never owns | Example |
| --- | --- | --- | --- | --- |
| Design primitives and components | `grimoire/primitives`, `grimoire/components` | Look, states, keyboard, ARIA | Game words, data, services | `button[lgButton]`, `lg-select`, `lg-panel` |
| Game presentation | `grimoire/game`, `grimoire/shell` | How a game thing looks: rarity hue and code, slot frame, sigil, currency amount | Rules: drop chances, unlock levels, inventory limits, what a slot may hold | `<button lgItemSlot rarity="Epic">` |
| Feature components | `features/**`, `layout/**` | Data, services, rules, adapters from DTOs to inputs | Hex colours, pixel sizes, a private copy of a Grimoire part | `inventory-grimoire/`, `rail-grimoire.component.ts` |

## 5. Proposed Design System folder structure

Keep the design system inside the app, as its own top-level folder beside `core/`, `shared/`, `features/` and `layout/`, and keep `design-system/` for what is not code: tokens, icons, docs and their scripts.

```text
LL/src/Presentation/ll/
├─ design-system/            source and docs; nothing here runs in the game
│  ├─ tokens.json            the only source of values
│  ├─ icons.json             the only source of icon drawings
│  ├─ docs/                  principles … governance, decision log
│  ├─ assets/                source images
│  └─ scripts/               build-tokens.mjs, build-icons.mjs, check.mjs
└─ src/app/grimoire/         what the game imports, as @grimoire
   ├─ index.ts               the public API
   ├─ tokens/                generated: tokens.css, tokens.ts, fonts/
   ├─ styles/                global: base.css (root size, focus ring, reduced motion,
   │                         .lg-root and .lg-legacy guards), layout.css (lg-stack,
   │                         lg-cluster, lg-split, lg-aside, lg-grid)
   ├─ core/                  icons (generated), format pipes, states, ids,
   │                         live values, the blocked-reason directive
   ├─ primitives/            button, icon, field, input, select, checkbox, radio,
   │                         switch, segmented, tag, tooltip, popover, menu,
   │                         dialog, toast, tabs, meter, skeleton, rule, table
   ├─ components/            panel, page, page-header, banner, folio, notice,
   │                         region-state, ledger, list, stat-figure, delta,
   │                         track, search-field, key-hints
   ├─ game/                  item-slot, item-link, rarity, loadout-slot, sigil,
   │                         constellation, emblem, level-plate, currency,
   │                         profile-identity, presence, journey-card, portrait,
   │                         condition, cooldown
   ├─ shell/                 game-shell, top-bar, nav-rail, stage, activity,
   │                         objective, chronicle
   ├─ testing/               component harnesses for feature specs (@grimoire/testing)
   └─ showcase/              the dev-only /grimoire route and its shell
```

One folder per component: `button.component.ts`, `button.component.css`, `button.component.spec.ts`, `button.showcase.ts` and `README.md` (the guidelines that today sit in `design-system/components/Button/`). File names keep the app's `.component.ts` suffix.

**Dependency rules**, checked by `check.mjs` because the repo has no ESLint:

1. `@grimoire` imports only Angular, the CDK and itself. Never `core/`, `shared/`, `features/` or `layout/`, never a DTO, never a service that calls the API.
2. Inside it, each folder imports only the folders before it: `tokens`, `styles` → `core` → `primitives` → `components` → `game` → `shell`. This is the README's layer model, made checkable.
3. Features import from `@grimoire` and `@grimoire/testing` only, never deep paths.
4. Adapters that turn game data into design-system inputs (today's `rail-grimoire.component.ts`, `chat-chronicle.ts`) stay in the feature or layout folder that owns the data.

### Trade-offs

| Option | For | Against | Verdict |
| --- | --- | --- | --- |
| `src/app/grimoire/` with an `@grimoire` path alias | One build, one `node_modules`, one test runner; the app's strict templates compile every component; a design-system change and its screens change together | Boundaries are a convention plus a check script, not the compiler | Recommended |
| `projects/grimoire` Angular library (ng-packagr) | A hard boundary; publishable | One consumer: the admin dashboard is a separate Angular 18 app with its own `package.json`. Adds a library build, path mapping and versioning nobody needs | Not now; only if a second Angular app must share it |
| Stay in `src/app/shared/components/grimoire/` | No move | A flat folder of 52 files heading for about 90, inside the legacy `shared/` zone, with no visible tiers | Move once, in phase 1 |

The move touches 8 importing files today. Every screen migrated before the move makes it more expensive, so it goes first.

## 7. Design-token architecture

Keep the token system as it is — `tokens.json` compiled to CSS custom properties, already tiered and documented per token — and make four changes: prefix every property `--lg-`, add breakpoints, emit a small `tokens.ts`, and allow a third, per-component tier only where a component needs a knob.

| Tier | Examples | Who may read it |
| --- | --- | --- |
| 1 · Palette | `slate-900`, `slate-900-a72` (48 colour tokens) | Tier 2 only; never a component (already the rule in each token's `usage`) |
| 2 · Semantic | `surface`, `ink-muted`, `line`, `gilt`, `arcana`, `danger`, `rarity-epic`, `space-4`, `radius-control`, `duration-fast` | Components, layout classes, `-grimoire` screen styles |
| 3 · Component | `--lg-panel-padding`, `--lg-meter-height`, declared on the component's `:host` with a tier-2 default | The component itself, and a screen that tunes one instance |

### The four changes

1. **Prefix.** Emit `--lg-ground`, `--lg-space-4`, and so on. Today's properties are bare globals (`--ground`, `--line`, `--focus`, `--tile`) on `:root` beside `--ll-*` and `--tw-*`. The docs keep the bare names, since they name tokens, not properties; only CSS changes, through the compiler and one scripted rename.
2. **Breakpoints.** CSS can't read a custom property inside `@media`, so components keep using container queries on the shell's regions (25 `@container` rules already do), and `check.mjs` checks that every literal width in a query matches a `breakpoint` token.
3. **`tokens.ts`.** The compiler also writes the values TypeScript needs: motion durations (today copied by hand into `LG_MOTION`), breakpoints for `BreakpointObserver`, and the overlay z-layers.
4. **Component tier, sparingly.** Add a tier-3 property only when a screen legitimately varies it. Density stays the `data-density` attribute it is today, set by a `density` input.

One theme stays (Grimoire), so there is no theming machinery. Reduced motion stays global, as now: `prefers-reduced-motion` and the `data-motion="reduced"` setting collapse every transition, so components need no motion code of their own.

## 8. Angular component API conventions

Every component follows the same twelve rules. They replace the React-to-Angular mapping table in the grimoire `README.md` and Governance · Code parity.

1. **Selectors.** Prefix `lg-`, Grimoire's existing prefix, rather than a new `ds-`: renaming would touch every selector, class, token and doc page and change nothing a player sees. An element selector for a part that owns its box (`lg-panel`). An attribute selector when the host must be a native element with its own semantics: `button[lgButton]`, `a[lgButton]`, `input[lgInput]`, `table[lgTable]`, `kbd[lgKey]`, a list's or a Ledger's rows (`li[lgListRow]`, `div[lgLedgerRow]`), and the interactive game parts (`[lgItemSlot]` on `button`, `a` or `div`). Behaviour without markup is a directive (`[lgTooltip]`, `[lgBlocked]`).
2. **The host is the box.** No `display: contents`. Set `:host { display: … }` and put the root class, `role` and state attributes on the host through `host` metadata. No input shares a name with a native attribute that acts on the host: Panel's `title` becomes a projected `lg-panel-title`, Ledger's becomes `heading`.
3. **Composition before configuration.** Structure is projected children, not arrays. A parent reads its children with `contentChildren()` only when it must coordinate them (keyboard, selection). Arrays stay only for long, uniform data nobody customises per row: Chronicle messages, suggestions from a service.
4. **Regions are child components**, not a generic slot directive: `lg-panel-header`, `lg-dialog-actions`, `lg-page-header-actions`. The template compiler rejects an unknown element; it never checked `lgSlot="asdie"`.
5. **Inputs.** `input()` and `input.required()`; string-literal unions for variants; `booleanAttribute` and `numberAttribute` transforms so `<lg-panel flush>` works. No configuration objects unless the value really is one thing (a list of shortfalls).
6. **Two-way state is `model()`**: `[(value)]`, `[(open)]`, `[(activeTab)]`. Form controls also implement `ControlValueAccessor`, so they work with Reactive Forms (already used by Market and the landing pages) and `ngModel`.
7. **Outputs** are `output()`, named for what happened, without `on`: `(closed)`, `(picked)`. Never re-emit what the host already fires: a press on `button[lgButton]` is the native `(click)`. `interactive` plus `(activate)` goes.
8. **Per-item templates** use a structural directive with a typed context (`ngTemplateContextGuard`): `<ng-template lgChronicleMessage let-message>`.
9. **Internal state is signals**: `signal`, `computed`, `linkedSignal` for state that resets when an input changes, `effect` only to sync with the DOM, `afterNextRender` instead of `setTimeout`. OnPush everywhere and nothing that needs Zone.js, so a later zoneless switch costs nothing.
10. **Dependency injection only for real context.** `LG_SHELL` stays. Services only where the API is imperative: `LgDialog`, `LgToaster`. No state services, no stores, no NgRx.
11. **Router-native.** Links are `<a>` with `routerLink`; the current item comes from `routerLinkActive` with `ariaCurrentWhenActive="page"`, not an `activeId` input. Components never inject `Router`.
12. **No game logic.** Inputs are display values (`rarity`, `level`, `label`, `remaining`), never DTOs or services. "Slot 3 unlocks at level 20" is decided in the feature and arrives as `state="locked" reason="Unlocks at level 20"`.

Inside a component, styling hooks are the host class (`lg-panel`), ARIA state and `data-*` attributes (`:host([aria-disabled='true'])`), not `is-*` classes toggled from TypeScript.

## 9. Styling strategy

Global tokens and a thin global base, each component's CSS in its own file under Angular's default emulated encapsulation, a few generated type and layout classes, and no Tailwind inside Grimoire.

The app styles with four things today: the legacy `--ll-*` tokens and `ll-*` classes (`src/styles.css`, 1,543 lines), Tailwind 3.4 utilities in about 103 templates, 34 SCSS and 5 CSS component files, and Grimoire's one global stylesheet. The frontend `AGENTS.md` already calls Tailwind's colour and typography classes legacy and keeps them out of Grimoire screens. So Tailwind is neither brought into Grimoire nor removed because of Angular: it retires with the last legacy screen, as the repo already intends.

| Layer | Where | Loaded | Holds |
| --- | --- | --- | --- |
| Tokens | `src/app/grimoire/tokens/tokens.css` | Global, first load | 281 `--lg-*` properties and `@font-face`; about 12.5 KB minified, 3 KB gzipped |
| Base | `src/app/grimoire/styles/base.css` | Global, first load | Root text size (100, 115, 130%), focus ring, `.lg-sr`, reduced-motion and forced-colours rules |
| Type and layout classes | `src/app/grimoire/styles/type.css`, `layout.css` | Global, first load | One class per type style, generated from the 10 type groups (`lg-type-body`, `lg-type-label`, …); `lg-stack`, `lg-cluster`, `lg-split`, `lg-aside`, `lg-grid` and the `lg-region` containers |
| Components | `<name>.component.css` beside each component | With the lazy route that uses it | That component's own template, nothing else |
| Screens | the `-grimoire` folder's own CSS | With the screen | Tokens and type classes only (checked) |

Rules:

- **Emulated encapsulation.** A component styles its own template and its host. It never reaches into projected content; that is why regions are child components that style themselves (section 8). No `::ng-deep`. About 100 selectors reach across components today (`.lg-shell .lg-pagehead`, `.lg-shell .lg-topbar`); they become inherited custom properties, the way density already works through `[data-density]`. `ViewEncapsulation.None` is used only in step 9, to move the CSS without changing it; each component switches to emulated when phase 3 re-shapes it.
- **Plain CSS**, with native nesting and container queries. Tokens are custom properties, so nothing needs Sass.
- **Utility classes only where they pay.** Type styles and layout, because features would otherwise retype font, size and leading triples and flex recipes. No colour or spacing utilities: those come from components and tokens.
- **No cascade layers yet.** Tailwind 3 and the legacy styles are unlayered, and unlayered rules beat layered ones, so a layered Grimoire would lose. Revisit when Tailwind is gone.
- **Raw values are errors.** `check.mjs` extends its raw-value check (hex colour, pixel font size, coloured shadow) to every component CSS file and to `-grimoire` screen folders.
- **The legacy guards stay where they are.** The `.lg-root` and `.lg-legacy` guards in `src/styles.css` (D-100, D-108) protect Grimoire from legacy element rules and stay until those rules go.

What goes: `src/styles/grimoire/components.css` and `sync-styles.mjs` (component CSS lives with components), and once tokens and base load globally, the `grimoire` bundle entries in `angular.json` and `lgLoadStyles()`. The largest component sections, Chronicle and GameShell, are 12.5 KB and 7.9 KB minified, inside the 20 KB `anyComponentStyle` warning budget. (Step 9, D-132: the first two went; the bundle and `lgLoadStyles` stay until the budget allows.)

## 10. Accessibility strategy

Keep every rule Grimoire already has (Foundations · Accessibility, Standards · States, D-087) and move the behaviour that implements them onto the Angular CDK, which the app already uses in 25 files. The goal is one overlay stack, one focus model and tests that prove both.

| Concern | Today | Target |
| --- | --- | --- |
| Semantics | Mostly right (combobox, listbox, progressbar, `nav`, `dl`), but hosts with `display: contents` | Native elements first: `button` acts, `a` navigates, `table` for tables, `dl` for Ledgers, `fieldset` and `legend` for radio groups |
| Focus visible | `focus-ring` token on `:focus-visible` | Same, in `base.css`; `FocusMonitor` only where a component needs the focus origin |
| Keys in composite widgets | `lgMoveKey` in Ledger, TabStrip, EntryList, Constellation | CDK `FocusKeyManager` (roving tabindex) and `ActiveDescendantKeyManager` (combobox, listbox), with Home, End, wrap and typeahead |
| Overlays | Own layer stack and document `keydown`; legacy CDK overlays beside it | CDK Overlay for tooltip, popover, select and search panels; `cdk/dialog` for dialog, drawer and confirm (focus trap, focus return, Escape, `aria-modal`, scroll block); `cdk/menu` for menus. Escape goes to the top overlay only, legacy or Grimoire |
| Stacking | 14 z-index tokens applied by the layer stack | The CDK overlay container sits at `z-overlay`; panes stack in open order; toast, tour and drag panes take their token through `panelClass` |
| Announcements | Own `lgAnnounce` with rate limit and de-duplication | CDK `LiveAnnouncer` behind a small `lgAnnounce` that keeps the rate limit and de-duplication |
| Blocked controls (D-087) | `lgWhy` directive and `LgWhyController` | `[lgBlocked]`: `aria-disabled`, still focusable, `aria-describedby` to the reason, the reason tip through `lgTooltip`, a press shows the reason |
| Tooltips | Native `title` in 9 components (keyboard users never see it); Ledger's own tip | `[lgTooltip]`: opens on hover and focus, Escape closes it, `aria-describedby`; never the only home of information that matters |
| Disabled | Rare; blocked is preferred | Same rule: plain `disabled` only when the limit is printed beside the control |
| Motion | Global CSS plus the `data-motion="reduced"` setting | Same; enter and leave through `animate.enter` and `animate.leave` (Angular 20.2) with CSS classes; no `@angular/animations` in Grimoire |
| Text size | rem everywhere; root at 100, 115 and 130% | Same; the showcase switches between the three |
| Forced colours | 3 `forced-colors` rules | Keep; Playwright emulates forced colours on the showcase |
| Shell drawer | `inert` plus `setTimeout` focus | `cdkTrapFocus` with auto-capture, `inert` on the rest, focus back to the opener |

How it is proven:

- **Harnesses.** Every interactive component ships a CDK test harness in `@grimoire/testing`, used by its own spec and by feature specs (`await rarity.select('Epic')`).
- **The parity scenarios, kept.** The 25 behaviour scenarios in `check-parity.mjs` are ported as harness specs before parity is deleted.
- **Axe on every showcase page** in the Playwright run (`@axe-core/playwright`): zero serious or critical violations.
- **A manual pass per migrated screen:** keyboard only and NVDA, at Default and Large text, as Foundations · Accessibility · Testing already asks.

## 11. Storybook or component showcase

Storybook is not used today. Build the showcase as a dev-only route inside the app instead, and revisit Storybook after an Angular 21+ upgrade.

The reason is fidelity, not effort. `@storybook/angular` supports Angular 18 to 22 on Webpack 5; its Vite framework with Vitest needs Angular 21 or later ([Storybook for Angular](https://storybook.js.org/docs/get-started/frameworks/angular)). This app builds with esbuild, runs PostCSS with Tailwind and `postcss-legacy-rem`, and depends on global styles and root text sizes. Storybook would compile the same components with a second toolchain and style pipeline, and could look right where the game looks wrong — D-100 happened exactly because the game's global styles overrode Grimoire's.

|  | Showcase route | Storybook (Angular, Webpack) |
| --- | --- | --- |
| Build | The app's own build, PostCSS and styles | A second Webpack build and style config |
| New dependencies | None (Playwright moves into `devDependencies`) | Storybook, its Angular framework, addons, Compodoc |
| Fidelity | Identical to the game | Close, not guaranteed |
| Controls panel | Not built; states are listed as stories | Yes |
| Docs pages | Links to each README and the docs | MDX |
| Accessibility check | Axe in the Playwright run | The a11y addon |
| Angular upgrades | No extra friction | Wait for a matching Storybook release |

### The showcase

- **Route.** `/grimoire`, lazy, matched only in dev mode (`canMatch: [() => isDevMode()]`); production builds replace the route file through `fileReplacements`, so the chunk isn't even emitted.
- **Entries.** Each component folder has a `*.showcase.ts` exporting a typed entry: a title such as `Primitives/Button` and named stories (`Primary`, `Secondary`, `Disabled`, `Pending`, `Locked`). The shape follows Storybook's CSF, so a later move is mechanical.
- **Stable URLs.** `/grimoire/primitives/button/primary`, `/grimoire/game/item-slot/legendary`: one URL per story, for screenshots and links.
- **Tree.** Foundations (colour, type, space, motion, icons), Primitives, Components, Game, Shell, Patterns.
- **Toolbar.** Density, text size (100, 115, 130%), reduced motion, frame (bare, in a Page, in an `.lg-legacy` host) and ground (plain, surface, backdrop art).
- **States.** Every state in Standards · States that a component supports has a story: `ItemSlot/Common` to `ItemSlot/Legacy`, `ItemSlot/Locked`, `Button/Insufficient`.
- **Regression.** `npm run grimoire:snapshots` opens every story at 1600×900 in Playwright, compares it with committed baselines and runs axe. This replaces the parity check as the safety net.
- **The Claude Design artifact.** The same script can save each story as static HTML, which is the "render the previews from the Angular components" step Martin agreed on 2 October.

## 12. Migration phases

Nine phases, each ending at a gate that must pass before the next starts; the game stays shippable throughout. Section 16 breaks them into 28 steps.


## 14. Risks

The biggest risk is losing the only safety net (parity) before its replacement exists; the order in section 16 is built around that.
