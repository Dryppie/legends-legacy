# Governance · Code

How Grimoire's code is organised and checked. The `lg-*` Angular components in `src/app/grimoire/` (paths here are from `LL/src/Presentation/ll/`) are the system's only implementation (D-127, D-133), imported as `@grimoire`. This page replaced Governance · Code parity when the reference edition, its catalog and the parity check were removed.

## Rules

**Must**
- Keep one implementation. A part is seen in the `/grimoire` showcase and its styles live beside it; there is no second edition, catalog page or copy of the styles (D-133).
- Give every part a folder in its tier, `src/app/grimoire/<tier>/<name>/`, holding `<name>.component.ts` (with the part's region components), `<name>.component.css`, `<name>.component.spec.ts` and `README.md`, and a showcase entry with a story for each state and variant it supports (D-129). A part without a spec yet is listed as debt by `check.mjs`; a new part has one.
- Keep the boundaries. Grimoire imports only Angular, the CDK, rxjs and itself, never the app, a DTO or a service that calls the API. Inside it a folder imports only the folders before it: `tokens`, `styles` → `core` → `primitives` → `components` → `game` → `shell`. The rest of the app imports `@grimoire` and `@grimoire/testing`, never a path inside them.
- Read every value from a token: `var(--lg-…)` in CSS, the constants in `tokens/tokens.ts` in script (D-131). A query width is a breakpoint token or a content tier, written out, since a query can't read a property.
- Pin behaviour in the part's spec, through its harness in `testing/` (D-130): what has focus, which state the part is in, what the reason tip says, which outputs fired, what screen readers are told. Assert behaviour, not how the markup is built.
- Pass the checks below before a change is done.

**Should**
- Give a new part, or one re-shaped in its plan step, the API conventions in section 8 of `ANGULAR_DESIGN_SYSTEM_PLAN.md` (repository root): the host is its box; composition before configuration; regions as child components rather than `lgSlot`; `input()`, `model()` and `output()`, outputs named for what happened, without `on`; native `button` and `a` hosts for controls; signals and OnPush; no game logic.
- Re-shape an existing part only in its plan step (phase 3), because its consumers, stories, spec and README change with it.

**Never**
- Edit generated code: `tokens/` (from `tokens.json`) and `core/grimoire-icons.ts` (from `icons.json`).
- Use `::ng-deep`, or a selector in one part's file that reaches into another part's markup, in new code. The ones that exist are listed for plan phase 3.
- Change the order of `styles/grimoire.css` without checking the snapshots: it is the cascade order (D-132).

## Styles

`styles/grimoire.css` imports the compiled tokens, the base and what stays global, in one order, the cascade order. The app builds it as its own stylesheet, `grimoire.css`, outside its first load, and `lgLoadStyles` adds it at startup (D-096, D-132); the tokens alone are 13 kB.

Every part's host is its box, and every part but Heading, Button and Table takes its CSS through `styleUrl` under Angular's default emulated encapsulation (D-136 to D-143). It styles its own template and its host (`:host`), never what is projected into it, so its regions are child components that style themselves (a few rules in `styles`). What a context changes reaches it as an inherited custom property (`--lg-panel-inset` from the surface a Panel sits in, `--lg-layout-gap` from a Page in the game's frame, the GameShell regions' `--lg-chronicle-*`, `--lg-meter-height` from a LevelPlate), a container query on a named container (`lg-shell`, `lg-topbar`), a region's `:host-context()` of its own part's class (a SectionRule's aside, the compact rail's header), or `LG_SHELL`, never as a selector from another part. What stays global is listed in Known gaps.

Every size under `src/app/grimoire/` and in a `-grimoire` screen folder is written for the 16px root; the legacy rem rebase (`scripts/postcss-legacy-rem`) leaves them alone (D-096).

## Tokens in code

Every token is a custom property with the `--lg-` prefix (`--lg-ink-muted`, `--lg-space-4`), and every type style a class (`.lg-type-body`) (D-128, D-131). The docs name tokens without the prefix. Script reads `tokens.ts`:

| Constant | Holds |
| --- | --- |
| `LG_DURATION`, `LG_EASING` | The motion durations in milliseconds and the easing curves |
| `LG_BREAKPOINT` | The shell's container breakpoints, in rem (`breakpoint-*`) |
| `LG_CONTENT_TIER` | Where a region's Narrow, Medium and Wide tiers start (`content-*`) |
| `LG_LAYER` | The layer stack's z-indexes (`z-*`) |

**General rules today.** Every part's host is its box (D-143). Projected content is the default content or a region component. A part that can be a control takes a native host — `<button lgItemSlot>`, `<a lgActivity>` — and its press is the native `(click)`; no part takes `interactive` or emits `(activate)` any more (D-138, D-139). A value the screen owns is a `model()`, bound with `[( )]`. Other events are outputs named for what happened, without `on`, except where that name is a DOM event the host would also fire (SearchField).

## Tests

- **Specs and harnesses.** Each part's spec drives it through its harness (`LgButtonHarness`, `LgTipHarness`, `LgPanelHarness`, …) from `testing/`, so it says what a player does and sees; a change to the markup changes only the harness. The 25 behaviour scenarios of the old parity check are specs (D-130). `testing/announcer.ts` reads the announcer, with the fakeAsync rules its queue needs.
- **The showcase and its snapshots.** Every story is compared with its per-platform baseline, and axe checks every entry (`npm run grimoire:snapshots`, D-129).

## Checks

From `LL/src/Presentation/ll`:

```text
node design-system/scripts/check.mjs    the generated code, the docs' bookkeeping, raw values, token names, query widths, boundaries, README and showcase entry per part
npm run build:development                compiles every lg-* component, through the showcase
npm run test:ci                          every spec
npm run grimoire:snapshots               every story against its baseline, and axe
```

A change is done when all four pass: no `check.mjs` error, no snapshot difference but the intended ones (their baselines updated in the same change) and no new serious or critical axe violation.

## Known gaps

- **Behaviour bug, pinned as a skipped spec** (fix in plan phase 3):
  - **Live list, `keep` after release.** A kept key that has left the data stays while the list is held, but drops out on `release()` (the player pressing "2 new listings"). Foundations · Motion (Live updates, rule 3) says it stays until the player picks another (`core/grimoire-motion.spec.ts`).
- **Window width in the new look's frame.** `dashboard-grimoire` (the edge swipe) and `chat-grimoire` (whether the docked Chronicle opens) compare `window.innerWidth` with 960px, while the shell's breakpoint is `breakpoint-shell`, 60rem of its container. At Large and Extra large text they disagree between 960px and 1,104 or 1,248px. Read `LG_BREAKPOINT.shell` against the shell's width when the frame is next touched.
- **Styles still global**: Heading's and Button's, whose classes other parts and screens set on their own elements, and the Table's, whose cells are the screen's own markup (D-146); the attention mark; the Chronicle's parts (D-141); a ProfileIdentity fact's link, the host's content (`base.css`); and the dialog's pane and scrim and the toasts' layer, which the CDK draws outside every component (`overlay.css`, D-145).
- **The first load is over its old limit.** It is 1,009.4 kB; the error budget is 1,050 kB since D-142 (the warning stays at 500 kB). The legacy screens' Angular Material loads `@angular/cdk/a11y` at startup, and the build keeps any part of that package a lazy screen uses beside it in the first load: the key managers added 6 kB that way (D-137), `ActiveDescendantKeyManager` 0.2 kB (D-140) and the GameShell drawer's `FocusTrap` 2.5 kB (D-141). The Dialog and the toaster added nothing to it (D-145); the chat's Menu and Popover added 8.8 kB, 6.2 kB of it the CDK's `FocusMonitor` (D-146). Taking Material's form field, input and icon out of the first load would win most of it back.
- **Parts without a spec**: `check.mjs` lists them as warnings.
- **Root size (D-096).** The game's root follows Grimoire: 100%, 115% and 130%. The legacy styles were written for the old 14px root, and the build multiplies their rem values by 0.875, so legacy screens keep their size at Default.
- **Fonts and body.** `src/index.html` loads the Google Fonts families and `src/styles.css` sets the root sizes; Grimoire's stylesheet sets neither, because it loads after the first render.
- **In the game's frame.** A migrated screen's host carries `lg-root`; the game's legacy element styles stop there, and its own styles live in a `-grimoire` folder (D-100). The Character Overview is the first.
- **Inside GameShell.** An unmigrated screen sits in an `lg-legacy` region in the stage (D-108). The game sets `--lg-legacy-*` to its body type, and its guards restart inside `.lg-legacy`, so the screen looks as it does in the old frame; a migrated screen inside it is a Page and stops them again.
