# Angular frontend instructions

- Use the existing Angular version and conventions.
- Prefer standalone components and signals where they match existing code.
- Keep API calls inside services rather than components.
- Do not introduce a new state-management library without explicit approval.
- Reuse existing UI patterns and shared components.
- Test loading, empty, error, and success states for new screens.
